Сравнение форматов сериализации (gj E1-8)

1. Цель
Сравнить JSON и MessagePack (msgpack) как кандидатов на формат payload
в протоколе оверлейной сети. Критерии:
1) размер(байт);
2) скорость сериализации/десериализации(мкс);
3) удобство валидации;
4) расширяемость.

2. Методика
Скрипт compare_serializers.py:
1) берёт 4 типичных payload (PING, FIND_NODE, NodeRecord, DATA);
2) сериализует каждый в JSON и msgpack;
3) измеряет размер;
4) измеряет время encode/decode;
5) выводит таблицу.

Запуск:
python scripts/compare_serializers.py

3. Результаты измерений
Sample         JSON (bytes)    msgpack (bytes)    Ratio    JSON enc (µs)   msgpack enc (µs)
-----------------------------------------------------------------------------------------------
PING                     51                 34     0.67             2.84               3.07
FIND_NODE               129                108     0.84             3.57               2.41
NodeRecord              455                407     0.89             5.19               3.31
DATA                    428                396     0.93             4.69               2.93
-----------------------------------------------------------------------------------------------
TOTAL                  1063                945     0.89

Выводы по размеру:
1) msgpack компактнее на 7–33% в зависимости от типа payload.
2) на маленьких сообщениях(PING) экономия максимальна(33%).
3) на больших(DATA) экономия меньше(7%), т.к. JSON-накладные расходы амортизируются длиной строк.

Выводы по скорости:
1) на encode: JSON иногда быстрее на PING из-за C-оптимизаций.
2) на decode: msgpack обычно быстрее(бинарный разбор).

4. Удобство валидации
Критерий	                JSON	                      msgpack
Читаемость глазами	        ✅ да	                ❌ нет (бинарник)
Отладка через cat/less	        ✅ да	                ❌ нет (нужен декодер)
Схемная валидация (jsonschema)	✅ зрелые библиотеки	⚠️ менее распространено
Проверка в pcap	                ✅ видно в Wireshark	⚠️ нужен плагин/декодер

Вывод: для отладки и приёмки (E1-3, E1-6, E1-7) JSON удобнее, т.к. журналы читаемы, pcap можно смотреть глазами, ошибки видны сразу.

5. Расширяемость
Критерий	                            JSON	                msgpack
Добавление нового поля	        ✅ обратная совместимость	✅ обратная совместимость
Пропуск неизвестных полей	✅ стандартно	                ✅ стандартно
Вложенные структуры	        ✅ нативно	                ✅ нативно
Бинарные данные	                ❌ base64 (33% overhead)	✅ нативно (bin тип)

Вывод: msgpack лучше для бинарных данных, но JSON требует base64, что увеличивает размер на 33% для бинарных полей.
