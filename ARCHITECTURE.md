# Архитектура проекта: Защищённая оверлейная сеть передачи данных на основе пиринговых протоколов

## Часть 1. Принятые проектные решения

### 1. Назначение документа
Документ фиксирует проектные решения по курсовой работе, обосновывает выбор
технологий и определяет границы этапов.

### 2. Цель работы
Разрабатывается оверлейная пиринговая сеть, работающая поверх обычной
IP-сети (underlay). Каждый узел - независимая программа на Python,
запускаемая в отдельном Docker-контейнере. 

Функции узлов:
1) обнаруживают друг друга через распределённую хеш-таблицу (DHT) на основе алгоритма Kademlia;
2) хранят подписанные записи о других узлах;
3) устанавливают защищённые сессии (TLS 1.3);
4) передают прикладные сообщения через туннели.

### 3. Выбор языка и версии
Язык: Python 3.13.3.

### 4. Библиотеки
1) asyncio лдя TCP-сервера/клиента
2) struct для кодирование заголовков
3) json для сериализации payload
4) cryptography для TLS
5) pytest, pytest-asyncio для Unit и integration тестов
6) pyyaml для загрузки конфигов
7) msgpack как альтернативный формат сериализации
8) pandas, matplotlib для обработки и визуализации данных

### 5. Параметры пилотной сети
1) N=5
2) K_BUCKET_SIZE=8
3) ALPHA=3
4) R=3
5) MAX_FRAME_PAYLOAD=1 МиБ
6) Тайм-аут соединения=30 с
7) Версия протокола=1

### 6. Формат сериализации payload
JSON (UTF-8).

### 7. Структура репозитория и принципы разработки
Структура:
ComNetKurs/
├── src/p2p/ # исходный код
├── tests/ # unit- и integration-тесты
├── configs/ # YAML-конфиги узлов
├── docker/ # Dockerfile и docker-compose.yml
├── scripts/ # вспомогательные скрипты
├── data/ # сырые данные экспериментов
├── docs/ # отчёты, схемы
├── ARCHITECTURE.md # этот документ
├── PROTOCOL.md # описание протокола
├── README.md # инструкция по запуску
└── pyproject.toml # зависимости

Принципы hfphf,jnrb:
1) Воспроизводимость: любое утверждение подтверждается командой, тестом, логом, pcap или CSV/JSON.
2. Тестируемость: unit-тесты для каждого модуля, integration-тесты для сценариев.
3. Регрессия: каждый этап включает проверку обязательных пунктов предыдущих этапов.
4. Документирование по ходу: PROTOCOL.md и README.md обновляются вместе с кодом.
